# ADR 0001 — 技术选型

- **状态**：已接受
- **日期**：2026-10-17
- **范围**：v1（本地优先，**不含同步**）

## 背景

重写一个本地优先的 markdown 笔记应用。之前的实现累积了大量与业务无关的复杂度：
一个 64KB 的状态上帝对象、二进制被塞进字符串表、编辑器与 markdown 语法反复打架。

这次只带走它的**设计信条**（见 [../philosophy.md](../philosophy.md)），实现从零开始。
两个既定前提：

1. **Web 与桌面同构推进**，Android 后置
2. **同步搁置** —— 但文件必须增量，将来接得上

## 判据

选型不从"哪个流行"出发，从这三条出发：

1. **没有服务器** —— 任何需要后端/账号的东西出局
2. **能力要能被结构强制，而不是靠自律** —— 优先选边界天然存在的方案
3. **一个人、两条宿主** —— 优先少依赖、少魔法、单进程构建

## 决定

| 层 | 选型 | 一句话理由 |
|---|---|---|
| 语言 | TypeScript（strict + `noUncheckedIndexedAccess`） | 领域模型全是路径/树/指纹，类型是主要文档 |
| 运行时 | Node ≥ 22 + pnpm | 前端与测试同一运行时 |
| 构建 | Vite | Tauri 与 PWA 都是一等公民 |
| UI | React 19 | 见下「被否」里的说明 |
| 状态 | **不装库**：core 自持 store + `useSyncExternalStore` | 旧项目的债就在一个上帝 store 里 |
| 编辑器 | **CodeMirror 6** | 源码即真相，`[[ ]]` 装饰是原生能力 |
| 样式 | Tailwind 4，令牌集中在 `src/styles.css` 的 `@theme` | 令牌化比 utility 本身更重要 |
| 桌面 | Tauri 2（**尚未接入**） | 小体积、Rust 侧可绕 CORS、v2 自带 Android |
| 移动 | 后置，**暂不定** | 见「待定」 |
| 哈希 | Web Crypto `SHA-1`，算 **git blob sha** | 唯一能跨进程/跨设备表达"同一份内容"的值 |
| 测试 | Vitest（`environment: 'node'`）+ 将来 Playwright | 测试环境本身就是 core 的边界 |
| Lint/格式 | Biome | 一个工具顶 ESLint + Prettier |

## 关键取舍

### 为什么 core 零 DOM，而且靠测试环境来守

`src/core` 不许 import React、不许碰 `window`。**这条不靠 lint 规则**——
core 的测试跑在 `environment: 'node'`，它一旦摸浏览器 API，测试当场红。

纪律会忘，环境不会。

### 为什么编辑器从 ProseMirror 换成 CodeMirror 6

旧实现近一半的坑来自 ProseMirror 那一族：序列化把 `[[` 写成 `\[\[`、
嵌入 HTML 被 micromark 转义、widget 不在排版体系里被全局样式污染、
同一套工具栏要写两遍（命令版 + 字符串改写版）。

CodeMirror 6 是"源码即真相"：没有序列化往返，上述整类问题在结构上消失；
`[[ ]]` / `#tag` 是标准 decoration，`[[` 补全就是标准 autocomplete；
包体从 1.1MB 降到 ~200KB。

**代价**：丢掉"渲染成真表格真图片"的重度所见即所得。用 live preview 缓解
（图片就地渲染、光标不在的行隐藏标记）。

### 为什么内容指纹必须是 git blob sha

将来无论接 GitHub 还是网盘，那个值都是"同一份内容"的唯一表达。
git blob sha 是 `sha1("blob " + 字节数 + "\0" + 字节)`，`crypto.subtle.digest` 直接算得出，
**零依赖**；若将来接 GitHub API，它与返回的 blob sha 直接相等。

反过来：现在存个别的算法，将来要么全库重算，要么做一次迁移。

⚠️ 注意区分两件事：**"算指纹"现在就要**（外部修改检测、`mtime` 不可信）；
**"内容寻址的数据结构"现在不要**（那是同步的形状，做了是投机）。

### 为什么搁置同步，却仍要求增量

同步的全部复杂度（三张树、冲突、推送范围、删除确认）都来自"要和另一个存储比对"。
搁下它，v1 塌成"一个把文件夹当后端的编辑器"，这是对的。

但**增量**是廉价而不可逆的保险：一次保存只写变化的文件、启动只读变化的文件。
这两条现在就有收益（启动快、不刷 mtime），将来是同步的天然入口。
**不为同步留抽象，只留一个可观测的变更信号。**

## 被否的方案

| 方案 | 为什么不要 |
|---|---|
| Electron | 体积与内存代价太大，Tauri 已经够用 |
| Svelte 5 / Solid | 运行时更省，但项目难点在树与同步语义，不在 UI 层；换框架会让每次卡住都要先怀疑框架 |
| Redux / Jotai / XState | 上帝对象的病根是"三种状态住进一个容器"，不是库选错了；手写 30 行 store 反而强制了边界 |
| Milkdown / ProseMirror / Lexical / Monaco | 见上；Monaco 是代码编辑器气质，太重 |
| CRDT（Yjs / Automerge） | 它的全部价值是自动合并，与信条「不替用户做决定」正面冲突 |
| SQLite-WASM / IndexedDB 当主存储 | 会成为第二个真相 |
| Next.js / SSR | 本地优先、没有服务器，用不上 |

## 后果

**好的**：直接依赖约 10 个；core 可被 Node 直接测试；两宿主共用一套领域逻辑。

**要认的**：
- 丢掉重度所见即所得，观感上要接受"更接近源码编辑器"
- 增量基线引入一个 `.dusk/state.json` —— 必须守住"它可安全删除"
- `mtime` 不可靠，`(size, mtime)` 只能当快筛，误判会多算一次哈希
- 浏览器端**没有目录监听**，桌面能真知道"文件被别人改了"，浏览器只能聚焦时抽查。
  这必须写进能力矩阵，并影响文案（不能说"已确认没变"，只能说"上次检查时没变"）

## 待定 / 待实测

- **移动端**：Tauri 2 mobile 还是 Capacitor —— 取决于将来要不要接非 GitHub 后端
  （WebDAV 的 CORS 必须走原生）。现在拍板等于拍一个没有信息量的板
- **依赖版本**：本机 shell 被 PowerShell 执行策略挡住，`node` / `pnpm` 尚未验证。
  首次 `install` 后逐个核实，别照抄
- **构建怪癖**：旧项目在本机需要绕开"目录级 rename 报 EPERM"与"递归删 180+ 文件永不返回"。
  这两条是**这台机器的环境事实**，不是代码结构，开工后要实测是否复现，别提前复刻补丁
