# 设计信条

这份文件是项目的**宪法**。改代码之前先读它；想推翻某一条，要先说清为什么。

## 一句话

> **你的文件夹就是笔记库，程序只是它的一个视图。**

所有下面的原则都是这句的推论。判断一个设计好不好，先问：
**它有没有让"笔记是一堆真文件"这件事变得更假？**

---

## 一、文件即真相

内存里的 `files` 只是磁盘的影子，不是本体。

- 磁盘上是什么，程序就得显示什么
- 程序改了什么，磁盘上就得是什么 —— **逐字节**
- 换一个编辑器改同一篇，结果必须是对的

**反面**：把笔记存进 localStorage / IndexedDB / SQLite。写是写进去了，但它不在用户的磁盘上 ——
换台机器没有、清缓存没有、想拿别的工具改一个字也够不着。

## 二、单一真相

凡出现"第二份数据"的地方，都要消掉。

- 笔记内容只存在文件里，任何缓存都不许被当成可写入的来源
- 同一份偏好不许有两个组件各自读一遍
- 派生数据（反链、标签、全文索引）是**缓存**，删掉能重建 ——
  可以存在，但必须能被安全删除

判据很简单：**这份数据坏了，用户会丢东西吗？** 会 → 它是真相，只能有一份。不会 → 它是缓存，随便。

## 三、不假装

界面说的每一句话，都得是它真的知道的事。

- 内容没落盘，就不能显示"已保存"，要说"暂存"
- 本地改过了，就不能还显示上次的比对结果，要立刻说"还没比对"
- 能力不具备，就不许给一个按了没反应的按钮，要标"待接入"
- 填了凭据 ≠ 连得上，这是两件事，要分开说
- **数字和它描述的东西必须同源**（"能调用 N 个工具"要从真实注册表算出来）

## 四、不替用户做决定

猜错一次就是丢字，所以能做"选"，就不做"猜"。

- 冲突不自动合并 —— 只给「用本机 / 用云端 / 两版都留」
- 删除不可逆，就必须先问
- 不自动把上次读的书翻开，只给一张「继续读」的卡
- 换仓库不搬旧库的东西，新库有什么就显示什么

唯一的例外，是**链接指向一篇不存在的笔记**时当场把它建出来 ——
因为链接写着呢，那篇就该存在。这是语义必然，不是替人做主。

## 五、增量与记账

- 一次保存**只写变了的文件**，不重写整个库
- 启动**只读变了的文件**，靠一份可丢弃的基线（`size` / `mtime` / 内容指纹）
- `mtime` 只当提示，**内容指纹才是定论**
- 写失败的文件**不许进基线** —— 否则下次会以为它已经存好了

## 六、防静默损坏

最危险的不是报错，是**不报错**。

- 二进制不走文本解码（解不出的字节变 U+FFFD，不可逆）
- 指纹按解码后的字节算，不按 base64 字符串算
- 保存前把转义还原回去，否则磁盘上的链接就不再是链接
- 导入 GBK 要有兜底，否则是一屏问号，而且不报错

每一条都要有**专门的测试钉住**。见 [invariants.md](invariants.md)。

## 分层：core 零 DOM

```
core  ← 纯逻辑，node 环境测试
  ↑
hosts / ui  ← 浏览器与 React 在这里
```

`src/core` 不许 import React、不许碰 `window` / `document` / `localStorage`。

**这条不靠 lint 规则自律，靠运行时**：core 的测试跑在 `environment: 'node'`，
它一旦摸浏览器 API，测试当场红。

## 两条红线

**不用 CRDT（Yjs / Automerge）。** 它的全部价值是自动合并，而第四条规定不自动合并。

**不用本地数据库当主存储（SQLite-WASM / IndexedDB）。** 它会成为第二个真相。
IndexedDB 只留一个用途：存浏览器给不出的目录句柄（活句柄序列化不进 localStorage，这是浏览器逼的）。
