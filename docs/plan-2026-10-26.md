## 二、新架构

### 2.1 左栏 = 两个页签：文件 / 工具（先做这两个）

顶部一条 VS 式页签，只有两档，后面的档位等树跑通再加：

| 页签 | 内容 | 本版 |
|---|---|---|
| **文件** | 当前仓库的**文件树**：仓库名 + 篇数 + 目录/文件行，按支持度标弱化（md 正常、图片/文本灰标、其他「系统打开」） | 做 |
| **工具** | 索引状态卡（时间 / 篇数 / 重建）+ 工具带：坏链 / 孤儿 / 标签整理 / 查重 / 回收站 | 做（计数可先接索引） |

**文件页不嵌第二层切换** —— 标签 / 搜索 / 视图将来是新的顶级页签，
不塞进文件页里。查询抽象仍留在 core，第一版只有一种：

```ts
type Query =
  | { kind: 'tree' }                    // 本版唯一：文件树
  | { kind: 'tag'; tag: string }        // 后置
  | { kind: 'search'; text: string }    // 后置
  | { kind: 'view'; id: string }        // 后置

runQuery(vault, index, query) → Path[]   // 纯函数，node 环境可测
```

每加一档页签 = 加一个 query 类型 + 一个新面板，壳不动。

### 2.2 中栏 = 查看器路由（UI 新增 registry）

```ts
type DocKind = 'md' | 'image' | 'text' | 'binary'
docKindOf(path) → DocKind
VIEWERS: Record<DocKind, Component>
```

| kind | 谁 | 能力 |
|---|---|---|
| `md` | `.md` | 三档（阅读 / 编写 / 原代码），唯一可写 |
| `image` | png/jpg/gif/webp/svg… | 只读查看（图床机制已有） |
| `text` | 其余文本（代码 / json / csv…） | 只读展示，第一版不做高亮 |
| `binary` | pdf / office / 压缩包… | 「用系统程序打开」（桌面端）；浏览器端**说明做不到**，不给假按钮 |

以后支持新格式 = 加一种 kind + 一个 viewer，壳不动。这就是 D1 的落地方式。

**树里显示什么**：文件夹里的**全部文件都显示**（文件即真相，藏起来就是撒谎），
但按支持度分三档：可编辑（md）/ 可查看（image/text）/ 只能交给系统（binary）。

### 2.3 右栏 = 当前文档的上下文

| 页 | 内容 | 状态 |
|---|---|---|
| 大纲 | h1-h4 | 已有，迁移 |
| 关系 | 反链 + 悬空链接 | 已有，迁移 |
| 属性 | frontmatter（只读）+ 文件信息（大小 / 修改时间 / 指纹） | 新增 |
| 附件 | 本篇引用的图片清单（点击跳转） | 新增 |

### 2.4 数据模型：两层一刀切

```
真相层（用户的文件夹）
  .md 正文（含 frontmatter）· 附件/ · 其他文件

投影层（.dusk/，可整体删除）
  state.json     基线记账（已有）
  index.json     全文 / 标签索引（可重建）
  views/*.json   保存的视图
  trash/         回收站（真文件，可搬回）
```

新不变量（随本方案进宪法）：

> **投影层整个删除后，不得丢失任何用户内容，只允许变慢。**
> 守它的测试：删掉 `.dusk/` 重开，笔记正文逐字节一致、所有文档仍可打开。

### 2.5 core 的新模块

```
core/model/     保留（不动）
core/markdown/  保留（不动）
core/query/     新增：Query 类型 + runQuery（纯函数）
core/index/     新增：索引构建（按基线指纹增量）+ 全文搜索
core/views/     新增：保存视图的读写
core/ports/     保留
```

`core` 零 DOM 的规矩不变 —— 新模块全部在 node 环境可测。

## 三、与宪法的调和（v1 的结论，保留）

| 直觉 | 宪法 | 设计 |
|---|---|---|
| 要索引 | 派生数据是缓存 | 索引住 `.dusk/`，可重建 |
| 要保存的视图 | 不许第二真相 | 视图也是文件，删了不丢笔记 |
| 要元数据 | 不许污染正文 | frontmatter 是正文的一部分，程序只读 |
| 要回收站 | 删除不可逆必须先问 | 回收站 = `.dusk/trash/`，真文件可搬回 |
| 要管多种文档 | 二进制不过文本解码 | 字节通道已有；只加查看器，不加编辑器 |

红线不变：无 CRDT、无 DB 主存储、core 零 DOM、增量落盘、不自动合并、md 是唯一可写格式。

## 四、`.note` 退役规则（砍功能 ≠ 删用户文件）

1. 程序不再识别 `.note` 目录：不当文档、不给入口、不进索引、不进搜索
2. 磁盘上的 `.note` 目录**原样保留**，树里作为普通目录显示，用户自己处置
3. **不提供自动转换** —— `.note` 转 md 会丢排版，那是"假装保留"
4. README / docs 写一条退役说明：什么时候砍的、为什么、旧数据在哪、怎么自己处理
