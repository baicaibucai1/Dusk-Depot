### 只做纯 markdown

笔记正文**只有 markdown + 公式 + 表格**（数学和表格是 markdown 的常见扩展，其他工具也认）。
曾经试过内嵌 HTML/CSS（字色、字号、对齐、提示框），**已经整块移除** ——
理由是那套要配合"隐藏源码 + 可视化面板"，改一次抖一次，把最基础的选字/移动光标体验弄坏了。
宁可少几个花哨功能，也要让人能正常写字。

## 图床

图片不进 markdown（它装不下字节），所以仓库里有一个**图床目录**：

```
仓库/
├─ 附件/                      ← 图床：粘贴/拖入的图片都落这儿
│  └─ 截图-20261018-112701-i6ur.png
├─ 笔记.md                    ← 正文里只留一条相对引用
└─ .zzq
```

- **粘贴**（Ctrl+V）或**拖入**图片 → 自动写进 `附件/`，光标处插入 `![](附件/xxx.png)`
- 文件名带时间戳 + 随机后缀，同名粘贴两次不会互相覆盖（覆盖就是丢数据）
- 图片按**字节**存：FSA / Tauri 直接写文件，浏览器暂存走 base64，不会被当文本搞坏
- 显示时读字节转 Blob URL —— 相对路径在浏览器里是加载不出来的
- 图不在仓库里时：正文照旧，图片位置显示一个灰色占位，**不假装加载成功**

## 这个项目要什么

- **笔记是你磁盘上的真 `.md`**：能拿别的编辑器改、能拿网盘备份、能随时换一个文件夹
- **没有服务器、没有账号**：所有东西在本机
- **增量落盘**：改一个字只写那一个文件，不重写整个库
- **不假装**：暂存就说暂存，没比对就说没比对，没做完的就说没做完

## 这个项目不要什么

- ❌ **不做同步**（这一版）—— 但文件必须增量，将来接得上
- ❌ **不做自动合并** —— markdown 没有可靠的合并单位，猜错一次就是丢字
- ❌ **不用 CRDT** —— 它的价值就是自动合并，正好是这里拒绝的东西
- ❌ **不用本地数据库当主存储** —— 那会成为第二个真相
- ❌ **不做第二种文本格式** —— 正文只有 markdown 一种（图片是附件文件，不是另一种笔记）
- ❌ **不做内嵌 HTML/CSS 富文本** —— 试过，为了它牺牲了选字手感，不值

## 设置

左栏最下面那个滑块图标，打开的是**渲染设置**——只放真的会影响阅读的几项：

| 项 | 范围 | 影响 |
|---|---|---|
| 字号 | 13–21 px | 正文基准，标题按 em 跟着缩放 |
| 行距 | 1.4–2.2 | 行与行之间 |
| 段间距 | 0–1.75 rem | 段与段之间 |
| 正文宽度 | 34–62 rem | 一行的长度 |
| 字体 | 无衬线 / 衬线 | 衬线用 Georgia + 宋体栈 |

改完**立刻生效**，不用保存；面板里带一小段实时预览。
设置存在 `localStorage['dusk.settings.v1']`，应用时写成根节点的 CSS 变量
（`--dd-fs` / `--dd-lh` / `--dd-pg` / `--dd-cw` / `--dd-font`）——
阅读模式和编写模式读的是同一批变量，所以调一次两边一起变。
## 只写别的工具也认的 markdown

一条硬规矩：**我们能渲染出来的，别人打开这个 `.md` 也必须能渲染出来。**
渲染结果只能来自文件本身，不能依赖只有本程序懂的约定。

| 语法 | 标准吗 | 别的工具看到 |
|---|---|---|
| 标题 / 列表 / 引用 / 代码围栏 | ✅ CommonMark | 一样 |
| `**粗**` `*斜*` `` `码` `` / 图片 / 链接 | ✅ CommonMark | 一样 |
| 表格 · `~~划掉~~` | ✅ GFM | 一样 |
| `$x$` · `$$…$$` | ⚠️ 扩展 | GitHub / Obsidian / Typora 都支持 |
| `[[双链]]` | ❌ 不是 markdown | 原样显示 `[[名字]]`（死文本） |

因此：**新链接一律写成标准 markdown** `[标题](相对路径)`。
工具栏的「插入链接」是个选择器，选好目标再插——写出去的是任何编辑器都认的链接。
旧的 `[[双链]]` 继续**只读兼容**：能渲染、能跳转、反链照算，但不再产生新的。

改名时两种写法都会跟着重写：`[[旧]]` → `[[新]]`，`](旧路径.md)` → `](新路径.md)`。
## `.note`：块笔记（实验）

模仿 Notion 的"以块为单位"，但**不放弃文件即真相** —— 只是把"一篇文档"换成了"一个目录"。

```
示例-块笔记.note/          ← 目录即文档（后缀 .note）
├─ .note                   ← 标记 + 格式版本
├─ meta.json               ← 标题、创建时间
├─ order.json              ← 顶层块的顺序（只存 id）
└─ blocks/
   ├─ b1.json              ← 一块一个文件
   ├─ b2.json
   └─ …
```

块的样子（`text` 存的是**行内 markdown**，不是富文本 delta）：

```json
{ "id": "b2", "type": "paragraph", "text": "这一段是一个独立的块。" }
```

### 为什么不是一个 content.json

一条纪律：**改一段只写一个文件**。

| 操作 | 写哪些文件 |
|---|---|
| 改正文一块 | `blocks/<id>.json` |
| 改标题 | `meta.json` |
| 加/删/移动块 | 那个块文件 + `order.json` |
| 什么都没改 | **一个都不写**（`diffDoc` 返回空） |

附带好处：块文件小、可 diff、可 grep；坏一块只丢一块，整篇还能打开。

### 第一批块（就三种）

| 块 | 长什么样 | 要点 |
|---|---|---|
| **标题** | **没有卡片边框**，粗体大字 | 它是页面上的标题，不该长得像一张卡 |
| **正文** | 卡片（圆角 + 细描边 + hover 微阴影） | 块内**支持 md 行内语法**，输入时就渲染（粗体/行内码/链接不用等失焦） |
| **图片** | 卡片，直接显示图片 | 图片进图库 `附件/`，块里只存路径；拖入或点选 |

旧的列表 / 待办 / 引用 / 代码 / 分隔线已经删掉，读旧文件时会降级成正文。

### 分栏容器（真正的多列布局）

> ⚠️ 分栏的操作条是**常显**的（不是 hover 才出现）。之前复用卡片的 hover 工具条，
> 结果按钮永远不显示 —— 功能在、但没人找得到。

分栏块顶上有一条：

```
分栏 · 3 列    拖列右边缘改宽度    [＋ 加一列]  [删除分栏]
```

每列底部有 `＋ 加一块`。鼠标移到列上时，列右上角显示 `列 · 34%`，列本身的底色会浮出来。

想做成"左栏两块叠着、中右各一块"这种版面，用 **分栏块**：

```
columns
  ├─ column (width: 34)  ← 一列里可以堆任意多块
  ├─ column (width: 27)
  └─ column (width: 39)
```

- 底部「添加块」里的 **▥ 分栏** 建一个两列容器
- 容器左上角的「＋」加列；每列底部的「＋ 加一块」往这列里再堆一块
- 每列右边缘可以拖宽度；列里内容跟整个分栏块存在**同一个 JSON**里
  （列里的块没有独立文件 —— 分栏是"这一块内部的排版"，不是独立文档）
- 列里可以放标题 / 正文 / 图片

### 自由排版：左右有界、上下无界的白板

不是文档流，也不是栅格 —— 是 **Freeform / Milanote** 那种白板。

每块自己记着三个数：

```
layout: { x: 0..100, y: 像素, w: 15..100 }
         ↑左边缘%    ↑距顶   ↑宽度%
```

- **拖到哪就停在哪**：横向位置不跟别人挤，右边留白是正常的（不用填满）
- **宽度随手拉**：拖块右边缘，100% 挡不住，15% 也不会更窄
- **上下无界**：画布随内容长高，往下拖多远都行
- **左右有界**：x 夹在 0..100 之间，窗口变宽时百分比跟着走，跑不出界
- **新块自动落到最下面**：没摆过的块（新建的、老文件的）依次往下堆，不会全叠在左上角

**程序绝不挪动已摆放的块** —— 位置一旦存下来就是用户的决定。
之前的实现会让"独占一行就自动拉满"，那是栅格思维，和自由排版冲突；现在删掉了。

### 白板模型：左右有界、上下无界

版面不是一个"能套分栏的容器树"，而是一块**有左右边界的白板**。每个块只说自己"想占横向几列"
（12 列栅格里的 `width`，落盘是数字），**实际多宽由这一行里有谁**决定：

| 这一行有谁 | 显示结果 |
|---|---|
| 只有它一个 | **铺满整行** |
| 6 + 6 | 各占一半 |
| 4 + 8 | 按 4:8 分 |
| 6 + 12 | 6 单独一行（铺满），12 另起一行 |

算法是纯函数（[`layout.ts`](src/core/note/layout.ts)）：`packRows` 按顺序打成行 →
`rebalance` 把每行按比例铺满 12 列 → 组件取自己那个值。**不去量 DOM**，否则会自激振荡
（量出"独占一行"→ 拉满 → 真的独占一行 → 永远回不到并排）。

拖动的语义也随之变了：

- 拖到某块的**左/右半边** → 两块都变 6 列，自动并排
- 拖到**上/下边缘**（60px 内的细带）→ 上下堆叠
- 拖一个块的**右边缘把手** → 改它想占几列
- 删掉邻居 → 剩下的块**自动铺满**，但它存的列数不变（再拖一块回来，又变回原来的比例）

### 块能左右排布

块有宽度字段：

```json
{ "id": "b3", "type": "paragraph", "text": "半宽块", "width": "half" }
```

容器是 `flex-wrap`，所以：

- `full`（默认）→ 独占一行
- `half` → 两个并排，第三个折行

卡片工具栏上的 `▭ / ▯` 一键切换整行 / 半宽。

### 引擎：ProseMirror（TipTap）

第一版是自己拿 `contentEditable` 拼的，**死在输入法上**：中文合成期间重写 DOM，
合成被打断，表现为卡顿、丢字、回车失效。现在换成 ProseMirror ——
输入法、选区、撤销、拖拽、剪贴板都由它管，我们只负责"块长什么样"和"怎么落盘"。

> 这条教训写在这：**编辑期间绝不重写 DOM**。要改内容就走编辑器的 transaction。

### 排版规矩（三条，别再拍脑袋）

1. **一个左基线**：标题、正文、图片、两栏里的文字，左边全部对齐同一个 x。
   做法：卡片自己有 12px 左右内边距（选中框不贴文字），画布用 `margin: 0 -12px` 把它抵掉。
   所以文字仍然落在文档标题那条竖线上，卡片又不会把字憋住。
2. **间距跟块类型走**：正文之间 5px，标题上方 22px，图片上下 16/6px。
   一律 12px 等于没有分组，读起来会散。
3. **两栏固定槽宽**：半宽 = `calc(50% - 12px)`，列间距 24px，两栏正好铺满，不多不少。
4. **半宽只是"允许并排"，不是"必须只占一半"**：这一行里右边没有邻居时，
   块会自动长满整行（`flex-grow: 1`）—— 否则右边空着、正文却在窄栏里硬折行。
   存盘里的 `width` 不动，再拖一个块过来它又变回半宽。

5. **工具条挂在块的左上方**：升到块顶之上、退回左侧留白，只在**悬停**时出现。
   压在块里会盖住边框和第一行字；放在块内右侧会误触删除（按钮看不见但能点）；
   只在悬停出现，是为了打字时不被浮层挡着。校验方式：工具条的矩形不能和任何别的块相交。
6. **选中只给一层很淡的阴影边**，不铺白底 —— 版面别跟着跳。

### 交互

- **回车 = 换行**（`hardBreak`，块内软换行），新块靠下面的「添加块」显式创建
- **拖动**行首 `⠿`：卡片抬起（放大 + 旋转 + 阴影），松手后其他块用 FLIP 动画平滑让位
- **拖到左右侧自动分栏**：不用点任何宽度按钮。拖到目标块的左/右半边（中间那条带），
  两块同时变半宽并排；拖到目标块的上/下边缘，则是上下堆叠
- **图片宽度自动识别**：按原始尺寸，≤ 520px 的小图自动半宽（两张小图自然并排），大图整行；小图按原尺寸显示，不拉伸
- **块宽可以拖**：鼠标移到块上，右边缘出现一条绿把手，拖它设置百分比宽度（20–100%），
  存进块 JSON 的 `width` 是数字；拖满 100% 回到整行。半宽（自动）和手动宽度是两套语义：
  半宽会自动长满，手动宽度不会
- **默认没有边框**：卡片平时完全透明，只有光标落在里面（选中）时才浮出淡淡的边和底色
- 保存防抖 500ms，只写变动的块文件
