### 只做纯 markdown

笔记正文**只有 markdown + 公式 + 表格**（数学和表格是 markdown 的常见扩展，其他工具也认）。
曾经试过内嵌 HTML/CSS（字色、字号、对齐、提示框），**已经整块移除** ——
理由是那套要配合"隐藏源码 + 可视化面板"，改一次抖一次，把最基础的选字/移动光标体验弄坏了。
宁可少几个花哨功能，也要让人能正常写字。

## 图床

图片不进 markdown（它装不下字节），所以仓库里有一个**图床目录**：

```
仓库/
├─ 附件/                      ← 图床：粘贴/拖入的图片都落这儿
│  └─ 截图-20261018-112701-i6ur.png
├─ 笔记.md                    ← 正文里只留一条相对引用
└─ .zzq
```

- **粘贴**（Ctrl+V）或**拖入**图片 → 自动写进 `附件/`，光标处插入 `![](附件/xxx.png)`
- 文件名带时间戳 + 随机后缀，同名粘贴两次不会互相覆盖（覆盖就是丢数据）
- 图片按**字节**存：FSA / Tauri 直接写文件，浏览器暂存走 base64，不会被当文本搞坏
- 显示时读字节转 Blob URL —— 相对路径在浏览器里是加载不出来的
- 图不在仓库里时：正文照旧，图片位置显示一个灰色占位，**不假装加载成功**

## 这个项目要什么

- **笔记是你磁盘上的真 `.md`**：能拿别的编辑器改、能拿网盘备份、能随时换一个文件夹
- **没有服务器、没有账号**：所有东西在本机
- **增量落盘**：改一个字只写那一个文件，不重写整个库
- **不假装**：暂存就说暂存，没比对就说没比对，没做完的就说没做完

## 这个项目不要什么

- ❌ **不做同步**（这一版）—— 但文件必须增量，将来接得上
- ❌ **不做自动合并** —— markdown 没有可靠的合并单位，猜错一次就是丢字
- ❌ **不用 CRDT** —— 它的价值就是自动合并，正好是这里拒绝的东西
- ❌ **不用本地数据库当主存储** —— 那会成为第二个真相
- ❌ **不做第二种文本格式** —— 正文只有 markdown 一种（图片是附件文件，不是另一种笔记）
- ❌ **不做内嵌 HTML/CSS 富文本** —— 试过，为了它牺牲了选字手感，不值

## 设置

左栏最下面那个滑块图标，打开的是**渲染设置**——只放真的会影响阅读的几项：

| 项 | 范围 | 影响 |
|---|---|---|
| 字号 | 13–21 px | 正文基准，标题按 em 跟着缩放 |
| 行距 | 1.4–2.2 | 行与行之间 |
| 段间距 | 0–1.75 rem | 段与段之间 |
| 正文宽度 | 34–62 rem | 一行的长度 |
| 字体 | 无衬线 / 衬线 | 衬线用 Georgia + 宋体栈 |

改完**立刻生效**，不用保存；面板里带一小段实时预览。
设置存在 `localStorage['dusk.settings.v1']`，应用时写成根节点的 CSS 变量
（`--dd-fs` / `--dd-lh` / `--dd-pg` / `--dd-cw` / `--dd-font`）——
阅读模式和编写模式读的是同一批变量，所以调一次两边一起变。
## 只写别的工具也认的 markdown

一条硬规矩：**我们能渲染出来的，别人打开这个 `.md` 也必须能渲染出来。**
渲染结果只能来自文件本身，不能依赖只有本程序懂的约定。

| 语法 | 标准吗 | 别的工具看到 |
|---|---|---|
| 标题 / 列表 / 引用 / 代码围栏 | ✅ CommonMark | 一样 |
| `**粗**` `*斜*` `` `码` `` / 图片 / 链接 | ✅ CommonMark | 一样 |
| 表格 · `~~划掉~~` | ✅ GFM | 一样 |
| `$x$` · `$$…$$` | ⚠️ 扩展 | GitHub / Obsidian / Typora 都支持 |
| `[[双链]]` | ❌ 不是 markdown | 原样显示 `[[名字]]`（死文本） |

因此：**新链接一律写成标准 markdown** `[标题](相对路径)`。
工具栏的「插入链接」是个选择器，选好目标再插——写出去的是任何编辑器都认的链接。
旧的 `[[双链]]` 继续**只读兼容**：能渲染、能跳转、反链照算，但不再产生新的。

改名时两种写法都会跟着重写：`[[旧]]` → `[[新]]`，`](旧路径.md)` → `](新路径.md)`。
## `.note`：块笔记（v1 画布 / v2 文档流）

模仿 Notion 的"以块为单位"，但**不放弃文件即真相** —— 只是把"一篇文档"换成了"一个目录"。

```
示例-块笔记.note/          ← 目录即文档（后缀 .note）
├─ .note                   ← 标记 + 格式版本 + 布局模式
├─ meta.json               ← 标题、创建时间
├─ order.json              ← 顶层块的顺序（只存 id）
└─ blocks/
   ├─ b1.json              ← 一块一个文件
   ├─ b2.json
   └─ …
```

### 两种布局，两个版本（互不迁移）

| | v1 · 画布 | v2 · 文档流 |
|---|---|---|
| 标记 | `{ "version": 1 }`（或没有 version） | `{ "version": 2, "layoutMode": "flow" }` |
| 块文件 | `text` 存**行内 markdown** | `content` 存结构化行内节点 |
| 排版 | 每块 `layout {x,y,w}` 自由摆放 | 只按 `order.json` 竖排，**没有坐标** |
| 回车 | 块内软换行 | 拆块（Shift+Enter 才是软换行） |
| 块类型 | 标题 / 正文 / 图片 / 分栏 | 段落、两级标题、三种列表、待办、引用、代码、分隔线、图片、分栏 |

打开时**只看标记**决定用哪个编辑器：v1 一个字节都不改（不自动升级、不重排、不写盘），
v2 走文档流。标记坏掉时按块文件的形状兜底判断（有 `content`/`items` 就是 v2），
宁可当成新版打开，也不拿画布的逻辑去覆盖它。

v2 的块长这样（列表层级是显式结构，不从 DOM 反推）：

```json
{ "id": "b2", "type": "paragraph", "content": [
  { "type": "text", "text": "重要内容", "marks": ["bold"] },
  { "type": "text", "text": " 内部链接", "marks": [{ "type": "link", "href": "笔记.md" }] }
] }
```

认不出的块不降级：存 `type: "unknown"` + 原始 JSON，界面上是一条灰条占位，
保存时原样写回 —— 新版本写的块，旧版本打开也不会被吃掉。

### 为什么不是一个 content.json

一条纪律：**改一段只写一个文件**。

| 操作 | 写哪些文件 |
|---|---|
| 改正文一块 | `blocks/<id>.json` |
| 改标题 | `meta.json` |
| 加/删/移动块 | 那个块文件 + `order.json` |
| 什么都没改 | **一个都不写**（`diffDoc` 返回空） |

附带好处：块文件小、可 diff、可 grep；坏一块只丢一块，整篇还能打开。

### v2 文档流：块菜单、斜杠、手柄

| 想干的事 | 怎么做 |
|---|---|
| 插一块 | 空行里敲 `/`，输入中文或拼音关键词过滤，↑↓ 选、回车插入 |
| 改块类型 | 悬停块左侧 → 点 `⠿` → 「转换为」里挑（正文/两级标题/引用/代码/三种列表） |
| 挪块 | 拖 `⠿`，落点是块的上/下边缘（画一条绿线） |
| 复制 / 删除 | 同一个菜单里 |
| 换行 | 回车拆块；Shift+回车是块内软换行 |
| 加格式 | 选中文字 → 浮出工具条（粗/斜/删/行内码/链接） |
| 退出列表 | 空列表项上回车；行首退格也能退出来 |

块粒度为**顶层节点**：一组列表算一块（拖动、转换都按整组走）。

### v1 画布的块（三种）

| 块 | 长什么样 | 要点 |
|---|---|---|
| **标题** | **没有卡片边框**，粗体大字 | 它是页面上的标题，不该长得像一张卡 |
| **正文** | 卡片（圆角 + 细描边 + hover 微阴影） | 块内**支持 md 行内语法**，输入时就渲染（粗体/行内码/链接不用等失焦） |
| **图片** | 卡片，直接显示图片 | 图片进图库 `附件/`，块里只存路径；拖入或点选 |

旧的列表 / 待办 / 引用 / 代码 / 分隔线已经删掉，读旧文件时会降级成正文。

### 分栏容器（真正的多列布局）

> ⚠️ 分栏的操作条是**常显**的（不是 hover 才出现）。之前复用卡片的 hover 工具条，
> 结果按钮永远不显示 —— 功能在、但没人找得到。

分栏块顶上有一条：

```
分栏 · 3 列    拖列右边缘改宽度    [＋ 加一列]  [删除分栏]
```

每列底部有 `＋ 加一块`。鼠标移到列上时，列右上角显示 `列 · 34%`，列本身的底色会浮出来。

想做成"左栏两块叠着、中右各一块"这种版面，用 **分栏块**：

```
columns
  ├─ column (width: 34)  ← 一列里可以堆任意多块
  ├─ column (width: 27)
  └─ column (width: 39)
```

- 底部「添加块」里的 **▥ 分栏** 建一个两列容器
- 容器左上角的「＋」加列；每列底部的「＋ 加一块」往这列里再堆一块
- 每列右边缘可以拖宽度；列里内容跟整个分栏块存在**同一个 JSON**里
  （列里的块没有独立文件 —— 分栏是"这一块内部的排版"，不是独立文档）
- 列里可以放标题 / 正文 / 图片

### 自由排版：左右有界、上下无界的白板

不是文档流，也不是栅格 —— 是 **Freeform / Milanote** 那种白板。

每块自己记着三个数：

```
layout: { x: 0..100, y: 像素, w: 15..100 }
         ↑左边缘%    ↑距顶   ↑宽度%
```

- **拖到哪就停在哪**：横向位置不跟别人挤，右边留白是正常的（不用填满）
- **宽度随手拉**：拖块右边缘，100% 挡不住，15% 也不会更窄
- **上下无界**：画布随内容长高，往下拖多远都行
- **左右有界**：x 夹在 0..100 之间，窗口变宽时百分比跟着走，跑不出界
- **新块自动落到最下面**：没摆过的块（新建的、老文件的）依次往下堆，不会全叠在左上角

**程序绝不挪动已摆放的块** —— 位置一旦存下来就是用户的决定。
之前的实现会让"独占一行就自动拉满"，那是栅格思维，和自由排版冲突；现在删掉了。

### 白板模型：左右有界、上下无界

版面不是一个"能套分栏的容器树"，而是一块**有左右边界的白板**。每个块只说自己"想占横向几列"
（12 列栅格里的 `width`，落盘是数字），**实际多宽由这一行里有谁**决定：

| 这一行有谁 | 显示结果 |
|---|---|
| 只有它一个 | **铺满整行** |
| 6 + 6 | 各占一半 |
| 4 + 8 | 按 4:8 分 |
| 6 + 12 | 6 单独一行（铺满），12 另起一行 |

算法是纯函数（[`layout.ts`](src/core/note/layout.ts)）：`packRows` 按顺序打成行 →
`rebalance` 把每行按比例铺满 12 列 → 组件取自己那个值。**不去量 DOM**，否则会自激振荡
（量出"独占一行"→ 拉满 → 真的独占一行 → 永远回不到并排）。

拖动的语义也随之变了：

- 拖到某块的**左/右半边** → 两块都变 6 列，自动并排
- 拖到**上/下边缘**（60px 内的细带）→ 上下堆叠
- 拖一个块的**右边缘把手** → 改它想占几列
- 删掉邻居 → 剩下的块**自动铺满**，但它存的列数不变（再拖一块回来，又变回原来的比例）

### 块能左右排布

块有宽度字段：

```json
{ "id": "b3", "type": "paragraph", "text": "半宽块", "width": "half" }
```

容器是 `flex-wrap`，所以：

- `full`（默认）→ 独占一行
- `half` → 两个并排，第三个折行

卡片工具栏上的 `▭ / ▯` 一键切换整行 / 半宽。

### 引擎：ProseMirror（TipTap）

第一版是自己拿 `contentEditable` 拼的，**死在输入法上**：中文合成期间重写 DOM，
合成被打断，表现为卡顿、丢字、回车失效。现在换成 ProseMirror ——
输入法、选区、撤销、拖拽、剪贴板都由它管，我们只负责"块长什么样"和"怎么落盘"。

> 这条教训写在这：**编辑期间绝不重写 DOM**。要改内容就走编辑器的 transaction。

### 排版规矩（三条，别再拍脑袋）

1. **一个左基线**：标题、正文、图片、两栏里的文字，左边全部对齐同一个 x。
   做法：卡片自己有 12px 左右内边距（选中框不贴文字），画布用 `margin: 0 -12px` 把它抵掉。
   所以文字仍然落在文档标题那条竖线上，卡片又不会把字憋住。
2. **间距跟块类型走**：正文之间 5px，标题上方 22px，图片上下 16/6px。
   一律 12px 等于没有分组，读起来会散。
3. **两栏固定槽宽**：半宽 = `calc(50% - 12px)`，列间距 24px，两栏正好铺满，不多不少。
4. **半宽只是"允许并排"，不是"必须只占一半"**：这一行里右边没有邻居时，
   块会自动长满整行（`flex-grow: 1`）—— 否则右边空着、正文却在窄栏里硬折行。
   存盘里的 `width` 不动，再拖一个块过来它又变回半宽。

5. **工具条挂在块的左上方**：升到块顶之上、退回左侧留白，只在**悬停**时出现。
   压在块里会盖住边框和第一行字；放在块内右侧会误触删除（按钮看不见但能点）；
   只在悬停出现，是为了打字时不被浮层挡着。校验方式：工具条的矩形不能和任何别的块相交。
6. **选中只给一层很淡的阴影边**，不铺白底 —— 版面别跟着跳。

### 交互

- **回车 = 换行**（`hardBreak`，块内软换行），新块靠下面的「添加块」显式创建
- **拖动**行首 `⠿`：卡片抬起（放大 + 旋转 + 阴影），松手后其他块用 FLIP 动画平滑让位
- **拖到左右侧自动分栏**：不用点任何宽度按钮。拖到目标块的左/右半边（中间那条带），
  两块同时变半宽并排；拖到目标块的上/下边缘，则是上下堆叠
- **图片宽度自动识别**：按原始尺寸，≤ 520px 的小图自动半宽（两张小图自然并排），大图整行；小图按原尺寸显示，不拉伸
- **块宽可以拖**：鼠标移到块上，右边缘出现一条绿把手，拖它设置百分比宽度（20–100%），
  存进块 JSON 的 `width` 是数字；拖满 100% 回到整行。半宽（自动）和手动宽度是两套语义：
  半宽会自动长满，手动宽度不会
- **默认没有边框**：卡片平时完全透明，只有光标落在里面（选中）时才浮出淡淡的边和底色
- 保存防抖 500ms，只写变动的块文件

### 还没做

- 任意深度嵌套 / 分栏容器（现在只有"半宽"这一档）
- `/` 斜杠命令
- 协同（这个格式天然适合以后做 op log）
## 书架：EPUB 电子书

左侧导航条的第二个入口。**它跟仓库是两套东西**：书和阅读进度存在书架目录里，
仓库的 `.zzq`、`.note`、FileMap 里不会出现任何书籍条目；换仓库、搬仓库都不影响书架。

```
书架目录/                    ← 设备级，默认 <应用数据>/bookshelf
├─ library.json             ← 清单：书目、大小、封面缩略图、CFI、百分比、书签
├─ 三体.epub                ← 书就是原文件（导入时复制，不动你的源文件）
├─ .trash/                  ← 删书的回收站（先挪进来，可还原）
└─ library.broken-*.json    ← 清单坏掉时的留档（不会删，书也不会丢）
```

**设置 → 书架 → 存储位置**：显示路径、可更换、可「打开书架文件夹」。
浏览器拿不到完整路径时，界面会明说"显示的是目录名称"。

换位置是**两阶段**的：选目录只把句柄拿在手里，点「搬迁 / 使用」之后才写配置和
IndexedDB 句柄。取消、关闭对话框、目标探测失败都不会动当前书架 —— 以前这里会
提前换句柄，重启后出现"界面旧目录、读写新目录"。

搬迁（`src/core/shelf/migrate.ts`）：

1. 目标必须存在、可写、**完全空**（子目录也算）、不是源目录本身、不互相嵌套；
2. 先把文件复制到目标下的 `.dusk-migrate-*`，不碰目标根目录；
3. 逐个比对大小，并校验清单能解析、书目数量一致、每本书的文件都在；
4. 校验通过后才从暂存目录挪到根目录，最后才切配置；
5. 任何一步失败只清理**本次创建**的文件，旧书架全程只读、仍然可用。
   搬迁成功后旧目录也不删，由用户自己确认清理。

导入规则（三个入口共用一套：文件选择器 / 浏览器拖放 / 桌面原生拖放）：

- 只收 `.epub`；单本上限 200MB。超限在**复制之前**就报文件名和大小。
- 内容相同的书按 SHA-256 判重，提示"已在书架中"并可打开原条目。
- 同名不同内容 → `书名 (2).epub`；写入前还会检查目标是否已存在，**任何宿主都不覆盖**。
- 损坏 / 带 DRM 的文件会删除本次复制进来的那份，并在「导入结果」里逐条说明原因。
- 一次多选/多拖：逐项处理，一项失败不影响其他项；可以取消，已成功的保留。
- 桌面端读某个源文件失败会明确列出，不再静默跳过。

DRM 判定只读 ZIP 中央目录和 `META-INF/encryption.xml` 一个小条目（条目数、目录大小、
解压后大小都有上限，挡 zip bomb）。**字体混淆**（`idpf.org/2008/embedding`、
`pdf/enc#RC`，或 CipherReference 指向 `.otf/.ttf/.woff`）不算 DRM，书照常读；
`xmlenc#aes*` / `adept` / `rights.xml` 才是。

阅读器（epub.js，BSD-2-Clause，见 [THIRD-PARTY-LICENSES.md](THIRD-PARTY-LICENSES.md)）：

- 目录跳转、左右方向键 / PageUp / PageDown 翻页（iframe 里获得焦点也能用）、当前章节与百分比。
- 字号 / 行距 / 版心宽度；浅色、护眼、深色三套主题（只作用在书页 iframe 里）。
- 书签：加、跳、删；同一位置不重复加；位置用 CFI，失效时回退到章节 + 百分比。
- 每本书的进度按 `bookId` 记账；换书前先写回上一本，旧阅读器卸载时的迟到事件会被丢弃。
- 关闭标签/切回书架会立刻把进度写回 `library.json`；重新打开恢复上次位置。
- iframe 默认 `sandbox="allow-same-origin"` —— **书里的脚本不执行**；外链先问一句，
  拒绝后留在当前位置；书内锚点自己跳，不弹确认。
- 打开失败给「重试打开 / 返回书架」；换一本正常书不会保留上一本的错误。

删除是**可恢复**的：文件先移到书架目录的 `.trash/`，清单保留条目（`trashedAt`）；
「回收站」里可以还原，也可以彻底删除。确认框会写清楚删的是书架里的副本、
你自己导入的原始文件不受影响。

并发与保存：

- 导入、清单写入、换目录走同一把锁；导入中不能重复导入，也不能换目录。
- 清单写入用**目录代次**隔离：旧目录的延迟保存（翻页进度等）绝不会写进新目录。
- 只有写成功才清待保存状态；失败保留改动、左栏常驻红条「书架清单没有保存」，
  显示原因并可「重试保存」。切目录/搬迁前会先 flush，写不进去就不切。

仓库里的 `.epub`：文件树会显示它，但点开只给"文件区不读电子书"的说明和两个入口
（添加到书架 / 去书架）。添加是复制一份进书架目录，仓库文件不动；拖 EPUB 到文件区
或 Markdown 编辑器只会提示"请拖到书架"。

拖放：

- 桌面端走 Tauri v2 原生 `onDragDropEvent`（物理像素 ÷ devicePixelRatio 再做命中测试）；
  浏览器走 `DataTransfer.files`。
- 拖到书架/阅读页 → 只导入 EPUB；拖到文件树目录 → 导入 md / 图片 / PDF；
  EPUB 拖到文件区会提示"请拖到书架"；拖到 Markdown 编辑器只收图片。
- 只有真正接收该格式的区域会亮起来（`data-drop-zone`），松手/取消立刻熄灭。

### 还没做

- 全文搜索、双栏对照、朗读
- 固定版式（fixed-layout）只做尽力显示，没有专门的缩放策略
- 书架的排序只到"最近阅读 / 书名"，没有自定义分组
- 200MB 上限内，浏览器导入仍会把整本书读进内存一次（桌面端走 Rust 复制，不经过 JS）；
  没有做分块哈希/流式读取
- 回收站没有自动清理与容量上限

## 验收

界面上每一条功能都有脚本在跑，不是靠眼睛：

```bash
scripts/cdp-check.ps1     # 应用层：建笔记/改名/置顶/分栏/拖宽/切仓库
scripts/cdp-editor.ps1    # 编辑器：选字/拖选/三档/工具条/划掉/表格/公式
scripts/cdp-table.ps1     # 表格：选行列、网格编辑、改单元格
scripts/cdp-image.ps1     # 图床：拖入图片 → 落盘 → 引用 → 显示
scripts/cdp-settings.ps1  # 设置：打开面板、拖字号、自定义字体、恢复默认
scripts/cdp-jump.ps1      # 跳转：双击双链切到那一篇、悬空链自动建
scripts/cdp-link.ps1      # 标准链接：插入 [标题](路径)、双击跳转
scripts/cdp-note.ps1      # .note（v1 画布）：三种块、拖到右侧分栏、回车换行、输入法、动画、自动宽度
scripts/cdp-flow.ps1      # .note（v2 文档流）：11 种块、斜杠菜单、手柄菜单、拖动排序、串线、保存失败重试、旧笔记兼容
```

全部走真实浏览器（CDP 驱动），断言读的是**渲染后的 DOM** 或文档本身，不是源码字符串。
